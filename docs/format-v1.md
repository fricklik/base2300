# Base2300 checked v1 — 形式仕様

元プロジェクト由来のCRC32付き形式。`encode` / `decode` の既定形式で、
圧縮候補の最短選択は [experimental](format-experimental.md) を参照。
パッケージのバージョンと、このwire形式のバージョンは別である。

## 出力文字集合

旧 [Base2200文字表](../src/base2200Alphabet.ts) の64字＋常用漢字2,136字を同じ順で保持し、
ひらがな50字とカタカナ50字を後ろへ追加する。合計2,300種類。

現代の基本かなは各46字なので、単に「五十音」から50種類は得られない。
各46字に `ゐゑゔっ`、`ヰヱヴッ` を加えて各50字と定義する。
文字集合と順序は [base2300Alphabet.ts](../src/base2300Alphabet.ts) に固定する。
出力に濁点の結合文字は使わないが、`ゔ` などはNFD/NFKDで分解されるため、出力を正規化しない。

文字表全体（UTF-8、改行なし）のSHA-256は次の値に固定する。

```text
3161548944eb8347658152a30e41677efe91342755ff8ebdfbcf5151dc1371cf
```

2,200から2,300に増やすだけでは、1文字あたりの理論容量は約11.103 bitから11.167 bitへの増加にとどまる。
今回の短文の改善は、固定符号による入力の圧縮と、付加情報を短くした形式によるもの。

## 入力の符号化

入力は最大4 MiBの任意のバイト列。有効なUTF-8の場合は以下の2経路を比較する。
不正UTF-8を含む場合はバイナリ経路を使用し、置換文字へ変換しない。

| 経路 | 先頭の版・モード識別子 | 内容 |
| --- | --- | --- |
| テキストv1 | `あ` | Unicodeの文字種ごとに固定の接頭語符号を割り当てる |
| バイナリv1 | `ア` | 元のバイト列を上位ビットから読む |

テキスト経路の符号は符号長順、同じ長さでは以下の文字表順にcanonical prefix codeを構成する。
これは入力文字のモデルであり、2,300種類の**出力文字集合とは別**である。

| 入力文字 | 符号長 |
| --- | ---: |
| `0`〜`9`、`a`〜`z` の順の36字 | 6 bit |
| `A`〜`Z` の26字 | 8 bit |
| 上記以外のASCII、コードポイント昇順66字 | 11 bit |
| 常用漢字2,136字とU+3041〜U+3096、U+30A1〜U+30FA、U+3000〜U+303Fの和集合、コードポイント昇順 | 13 bit |
| 上記以外のUnicode scalar | 13 bitのエスケープ＋コードポイント21 bit |

13 bitの文字グループは2,376字で、エスケープ符号はその直後に割り当てる。
未知の漢字・絵文字・結合文字もエスケープで完全復元する。BOM、NUL、改行、文字の正規化形を保持する。
例文 `Base2300 packs the same bytes into fewer characters.`（52字）は
小文字・数字43字、大文字1字、空白と句点8字なので、`43×6 + 1×8 + 8×11 = 354 bit`。
UTF-8の416 bitをそのまま基数変換する場合より短い。

各経路の末尾に元バイト列のCRC-32/ISO-HDLCを32 bit追加し、次節の文字列へ変換する。
CRCの初期値と最終XORは `0xffffffff`、反転実装の多項式は `0xedb88320`。
得られた符号なし32 bit整数は**最上位ビットから**追加する。
UTF-8 `123456789` に対するCRC値は `0xcbf43926` となる。
両経路の**実際の全出力コードポイント数**を比較し、少ない方を採用する。同数ならバイナリ経路。
UTF-8容量では選ばない。また元テキストへ置き戻す分岐は設けない。
CRCは偶発的な破損検出用で、暗号化や改ざん防止ではない。

## 数値からBase2300へ

圧縮ビット列とCRC32を先頭から244 bitずつ区切る。最後のブロックは1〜244 bit。
各ブロックの先頭へ長さを保持するための `1` ビットを付け、その整数を2300進数で上位桁から書く。
先頭ゼロ桁を追加しない。入力ビット列がゼロで始まっても、この目印でそのゼロを復元できる。

244 bitの完全ブロックは、目印込み245 bitが常に22桁となる。
復元時は本体を左から22文字ずつ読み、途中のブロックが244 bit、最後が244 bit以下であることを検査する。
巨大な入力全体を1個のBigIntにしないため、符号化する各整数の幅は最大245 bitとなる。
復号時にこの範囲を超えるブロック値を受け取った場合は拒否する。

ビット列の終端は最後の整数の最上位ビットから分かり、末尾32 bitをCRC32として分離できる。
別途十進数のバイト長、16進CRC文字列、コロンなどを付ける必要がない。
例文は354＋32＝386 bit。完全ブロック1個（目印込み245 bit → 22桁）と残り142 bit
（目印込み143 bit → 13桁）で、識別子1字を加えて36文字になる。

識別子を含む全出力が2,300種類の文字集合内にある。
文字表・符号モデル・ブロック構造を変える場合は、新たな版識別子を割り当てる。
独立版の基本APIは、この2種類の識別子だけを受け付ける。別形式の自動判別は行わない。

## 復元と互換性

文字集合、先頭ゼロ、ブロックの範囲、途中ブロックの長さ、末尾の不足、未定義の接頭語、
不要なエスケープ、不正なUnicode scalar、復元後の4 MiB上限、CRC32を検査する。
空白や改行を勝手に除去せず、不完全な貼り付けはエラーにする。
旧Base2200 v1はこの独立パッケージの対象外。

実装のフレーム長上限は `1 + ceil((4,194,304 × 8 + 32) / 244) × 22`、
すなわち識別子を含む3,025,419コードポイント。
読み取り前のUTF-16長検査には、その2倍の `MAX_BASE2300_TEXT_LENGTH = 6,050,838` を使う。
これは符号化文字列のUTF-8容量を4 MiBに制限するものではない。
フレーム長に収まっていても、構造や復元後のサイズが不正なら拒否する。

ライブラリとCLIのバイトAPIは元のバイト列を返す。ファイル名・MIME型は符号化データに含めない。
